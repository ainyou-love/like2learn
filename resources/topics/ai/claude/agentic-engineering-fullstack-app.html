#TL;DR — the 60-second version

A principal engineer builds a real full-stack iOS app — from empty terminal to working end-to-end — by talking to a single orchestrator agent and letting it delegate everything.

  • He builds Eddie's Wallet, a virtual-money allowance tracker for his son, with a parent mode and a read-only child mode.
  • He talks to one agent (First Mate, the "captain → first mate" pattern). It spins up parallel crewmates for market research, tech research, UX, backend, iOS and infra.
  • The whole build runs on an efficient model (GPT-5.6 "Luna"), not the top model — deliberately, to prove you don't need the best model for everything.
  • Planning and review happen in Lavish — interactive HTML artifacts with editable decisions and diagrams — instead of reading walls of Markdown.
  • The human's job shrinks to judgment at decision points: rejecting an over-priced hosting recommendation, cutting over-engineering, correcting spelling, approving secret access.
  • Result: native iOS/iPad app + Fastify/Postgres backend on a ~$5/mo Hetzner VPS, Apple Sign-In working, real data in the cloud, verified end-to-end in the simulator — ready for TestFlight.
Core idea

Get the right thing settled (market fit, requirements, architecture, cost) through cheap parallel research and interactive review — then let agents do the thing right (build, deploy, test) with the human only stepping in for judgment.

#Who & what

Kun Chen — an L8 principal engineer who has worked at Meta, Microsoft and Atlassian — records his agentic-engineering workflow building a real project from scratch. This is the follow-up to an earlier workflow video that reached 600k views.

The project is Eddie's Wallet, an app his son asked him to build: a tracker for a child's allowance that today they manage on paper. The twist is that it should also teach basic financial concepts — balance, loans, credit cards, interest, repayment — introduced gradually and naturally.

Requirements he rambled up front

iOS-first (his son uses an iPad); a parent mode (deposit / manage / withdraw) and a read-only child mode; money is strictly virtual, never real; data is cloud-persisted and portable across his phone and the child's devices; and two kick-off tasks in parallel — market research (does this already exist?) and technical research (how do we build it full-stack?).

#The orchestration model

One captain, one first mate, many crewmates — the pattern that carries the whole session.

Instead of managing many agents, Kun talks to exactly one: the First Mate. He is the "captain"; the first mate juggles everything and dispatches work to crewmates (sub-agents). This kills the two costs of multi-agent work — cognitive load and context-switching.

Crucially, each crewmate is a normal agent in a normal terminal tab (managed by Herder), so unlike hidden sub-agents in most harnesses, Kun can drop into any crewmate to observe or steer it — and First Mate tears the tab down automatically when a task finishes.

Visualization 2 · Captain → First Mate → Crewmates
Calm mode

In the PI agent, First Mate runs in calm mode: all the tool-call noise disappears, leaving only your prompt and First Mate's reply. Kun's take: with older, weaker models you needed to watch every tool call to steer; with today's models that's rarely necessary, so hiding the noise makes the experience clean.

01Setup

First ground rule to First Mate: every task, every crewmate runs Luna at x-high reasoning. He also creates the local eddies-wallet repo with a dummy README and initial commit.

02Kickoff ramble

His deliberate style: "I just ramble… and let the agent figure things out."

03Parallel research

First Mate spins up two crewmates in two tabs. The market scout finds no existing iOS app matching the full brief (virtual-only, parent-controlled, child read-only) and recommends building rather than installing an alternative. The technical scout builds a backlog, notes open decisions, and fetches Apple docs. Both confirmed running Luna as instructed.

04Technical planning in Lavish

Rather than read a 351-line report, he asks for the review in Lavish. The scout recommends hosted Supabase; he pushes back on cost and puts a self-hosted VPS on the table, adding the auth story (Apple Sign-In now, Google later). He annotates the rendered architecture diagram directly — deleting over-engineered pieces like audit events and encrypted export to keep initial scope minimal.

05Front-end prototyping

While the backend is being researched, he kicks off a parallel UX stream: clickable HTML wireframes in Lavish (not iOS code) for the key screens and user flow. He plays with them — family setup, device pairing, child read-only view, parent unlock — and gives feedback (use local currency not "tokens", remove a redundant "recent activity" button). Wireframes only; polish comes later.

06Market inspiration → PRD → GitHub

He has First Mate mine the market research for concepts worth borrowing (money buckets, activity timeline, contextual lessons tied to real actions, gentle gamification — which he's wary of) and keep only what fits. Feedback is folded into a PRD written as the repo README, then committed and published as a public GitHub repo (he fixes a misspelling of "Eddie" both locally and on GitHub). Switches to a direct-PR workflow with First Mate auto-merging reviewed PRs.

07Design system

Uses Claude Design to build a design system (for future consistency), pointed at the repo README. Opus is overloaded, so he tries Sonnet — "I also don't think the problem is too complex." Iterates: fixes uncentered text, and pushes hard on "this doesn't feel like a children's app" until it gets a friendlier, bouncy, piggy-bank feel. Also commissions app-icon options and exports the whole system as a zip.

08Backend build (3 parallel streams)

First Mate creates three parallel work streams: backend API, DB schema/boundaries, and VPS foundation with backups + deployment automation. He redirects infra to use OpenTofu for declarative infrastructure, and grants Hetzner access via an Atomic Vault token — approving each production-secret access individually rather than blanket-allowing.

09Apple Developer setup (browser automation)

He confirms a paid Apple developer membership and, instead of clicking through App Store Connect himself, tells First Mate to drive his real Chrome browser (via remote debugging / DevTools) to register the app ID and Sign-In capability. It hits a display-name validation error, he coaches it, and it succeeds on retry.

10Integration & DNS

He supplies a Cloudflare API token (also vaulted) and a domain, and the agent adds a subdomain record pointing at the VPS, bringing the backend live over verified HTTPS. He splits repos: the iOS app stays in the open-source repo, the backend moves to a private one. Only one production environment — he cuts the agent's tendency to set up separate dev/prod tiers as over-engineering.

11End-to-end testing & fixes

The iOS app was initially just a mock, so he pushes to real end-to-end integration: sign in with a real Apple account in the simulator and hit the real backend. The agent self-tests in the simulator, catches a wrong-address bug and an Apple AuthKit issue, and fixes them. He also has it neutralize the copy so "Eddie" isn't assumed to be every user's name. "Don't ask me unless there's something only I can do."

12Architecture review & ship

While bugs are being fixed, he runs a backend architecture review in Lavish (endpoints, auth flow, DB schema) and finds nothing over-engineered. Final gate: he signs in with his real Apple account in the simulator, adds $10 in parent mode, sees it in the child view, signs out and back in — data persists from the cloud. It works end-to-end. Next step: a TestFlight build onto his son's iPad. All of it on Luna, with Sonnet for design.

#Where the human still steered

The workflow is agent-driven, but a handful of judgment calls were unmistakably human.

  • Rejected the expensive recommendation. The model pushed hosted Supabase at $25–40/mo based on wrong VPS cost data. Kun overrode from experience: a low-cost Hetzner VPS at ~$5/mo. "The only place Luna wasn't smart enough."
  • Cut over-engineering repeatedly. Deleted audit events / encrypted export from the plan; refused separate dev/prod environments for a three-user MVP. GPT-5.6 "has a tendency to over-engineer."
  • Set scope boundaries. Apple Sign-In now, Google later; wireframes not polish; no No Mistakes guardrail while there's no code to review.
  • Guarded production secrets. Approved each Vault access individually rather than blanket-allowing, wanting to see every command touching Hetzner/Cloudflare.
  • Caught product/detail bugs. Fixed the "Eddie" misspelling; flagged that "Eddie" shouldn't stand in for every user; chose USD over invented "tokens/points."
  • Pushed the agent to keep going. "Don't ask me unless there's something only I can do" — agents are capable as long as they keep trying; they just need encouragement.

#Principles & lessons

1 · One agent to talk to

Delegating through a single First Mate removes cognitive load and context-switching. You dump thoughts; it figures out which crewmate to steer, when to spawn tabs, and when to close them.

2 · Parallelize aggressively

Market + technical research, backend + frontend, three infra streams at once. "First Mate is always busy, not just sitting around." Prototype multiple things simultaneously to make fast progress on full-stack work.

3 · You don't need the best model for everything

An efficient model (Luna) carried a real build end-to-end; Sonnet handled design when Opus was overloaded. Reserve the top models for genuinely hard problems.

4 · Interactive planning beats walls of text

Lavish artifacts — editable decisions, annotate-any-element feedback, rendered diagrams — surface hidden requirements and are far easier to steer than a 351-line Markdown report.

5 · Treat compaction as an implementation detail

Four auto-compactions, no visible loss — because OpenAI's server-side compaction is strong and First Mate persists task state to files. Let the agent run and compact; don't micromanage the context window.

6 · Guardrails scale with delegation

As you hand agents more power, secrets management (Atomic Vault) and validation pipelines (No Mistakes) become more important, not less — you're no longer watching every tool call.

7 · Infrastructure as code

Declarative OpenTofu config means the machine and resources are auditable, committable, and reproducible — not clicked together by hand.

Watch-outs he named

Efficient models can be wrong on facts (VPS pricing) and tend to over-engineer — keep human judgment at cost and scope decisions. Be deliberate about which changes need a review guardrail. And giving an agent your live browser/production secrets demands per-action approval.
