02

Tool call là gì

2.1 Mental model một câu

Claude không bao giờ tự thực thi công cụ. Claude chỉ đề xuất; một chương trình bao quanh (harness) quyết định có chạy hay không, chạy thế nào, rồi báo kết quả lại.

Harness có thể là:

  • Backend của bạn (khi dùng Messages API với custom tool).
  • Claude Code hoặc Claude Agent SDK.
  • Ứng dụng claude.ai.
  • Hạ tầng của Anthropic (với server tool như tìm kiếm web).

2.2 Giải phẫu một tool call

Một tool call gồm ba mảnh:

  1. 1Ứng dụng khai báo · tool definitionTên, mô tả, JSON Schema của đầu vào
  2. 2Claude đề xuất · tool_use“Tôi muốn gọi tool X với input Y”
  3. 3Harness thực thi · tool_resultKiểm tra quyền, chạy, gửi kết quả kèm đúng id

Ba mảnh của mọi tool call, dù tool nằm ở Anthropic, trong Claude Code, trên MCP server hay trong backend của bạn.

Tool definition (gửi trong request):

json
{
  "name": "tra_don",
  "description": "Tra trạng thái đơn hàng theo mã đơn. Dùng khi khách hỏi đơn đang ở đâu.",
  "input_schema": {
    "type": "object",
    "properties": {
      "ma_don": { "type": "string", "description": "Mã đơn, dạng DH-xxxx" }
    },
    "required": ["ma_don"]
  }
}

tool_use (Claude trả về trong content, kèm stop_reason: "tool_use"):

json
{
  "type": "tool_use",
  "id": "toolu_01ABC",
  "name": "tra_don",
  "input": { "ma_don": "DH-1024" }
}

tool_result (harness gửi lại trong message user kế tiếp):

json
{
  "type": "tool_result",
  "tool_use_id": "toolu_01ABC",
  "content": "{\"trang_thai\": \"dang_giao\", \"du_kien\": \"2026-10-14\"}"
}

2.3 Vòng lặp agent

Các giá trị stop_reason liên quan trực tiếp tới tool:

Giá trị Ý nghĩa với tool Harness làm gì
tool_use Claude chờ harness chạy tool phía client Thực thi, gửi tool_result, gọi lại
pause_turn Vòng lặp server tool (phía Anthropic) tạm dừng Gửi lại hội thoại để Claude đi tiếp
end_turn Đã xong Dùng kết quả
max_tokens Bị cắt, có thể cắt ngang giữa một tool_use Không thực thi tool bị cắt dở

pause_turn chỉ liên quan tới server tool. Khi Claude chờ tool phía bạn, lý do dừng luôn là tool_use.

3.3 Hai điểm hay nhầm

Skill không phải tool. Skill là thư mục có SKILL.md (hướng dẫn) và có thể kèm scripts/. Khi Claude chạy script, model chỉ thấy một tool call kiểu Bash: python scripts/tinh_phi.py. Không tồn tại block skill_use.

MCP là giao thức, không phải loại tool. Cùng một MCP server có thể được dùng qua Claude Code, claude.ai, Messages API (MCP connector) hoặc backend của bạn đóng vai MCP client. Cách dùng quyết định ai thực thi và ai kiểm soát (xem 5.3).

05

Ba cơ chế chi tiết: Message, Skill, MCP

5.1 Tool trong Message (Messages API)

Cách hoạt động

Backend của bạn chính là harness: khai báo tool, nhận tool_use, tự thực thi, gửi tool_result, lặp tới khi xong.

text
User ─▶ Chat backend ──(tools=[…])──▶ Claude API
             ▲                             │ tool_use
             │◀────────────────────────────┘
             ├─▶ Business API (backend tự gọi, biết user là ai)
             └──(tool_result)──▶ Claude API ─▶ … ─▶ end_turn ─▶ User

Các tham số điều khiển

Tham số Tác dụng
tools Danh sách tool Claude được phép đề xuất
tool_choice: auto Claude tự quyết có dùng tool hay không (mặc định khi có tools)
tool_choice: any Bắt buộc dùng ít nhất một tool
tool_choice: {type: tool, name} Bắt buộc dùng đúng tool chỉ định
tool_choice: none Không cho dùng tool
disable_parallel_tool_use Trong tool_choice: chỉ cho tối đa một tool call mỗi lượt
strict: true (trên từng tool) Đảm bảo input của tool đúng JSON Schema

Vòng lặp tối thiểu (Python, minh họa)

python
import anthropic

client = anthropic.Anthropic()
MAX_STEPS = 10

def run_agent(user_text, tools, executors):
    messages = [{"role": "user", "content": user_text}]
    for _ in range(MAX_STEPS):
        resp = client.messages.create(
            model=MODEL, max_tokens=2048, tools=tools, messages=messages
        )
        messages.append({"role": "assistant", "content": resp.content})

        if resp.stop_reason == "end_turn":
            return resp
        if resp.stop_reason == "tool_use":
            results = []
            for block in resp.content:
                if block.type != "tool_use":
                    continue
                try:
                    output = executors[block.name](**block.input)   # kiểm tra quyền bên trong
                    results.append({"type": "tool_result",
                                    "tool_use_id": block.id,
                                    "content": output})
                except Exception as e:
                    results.append({"type": "tool_result",
                                    "tool_use_id": block.id,
                                    "content": f"Lỗi: {e}",
                                    "is_error": True})
            messages.append({"role": "user", "content": results})
            continue
        if resp.stop_reason == "pause_turn":
            continue                      # gửi lại để server tool đi tiếp
        handle_other(resp)                # max_tokens, refusal, giá trị lạ…
        return resp
    raise RuntimeError("Vượt số bước tối đa")

Điểm cần chú ý trong vòng lặp:

  • Parallel tool use: một response có thể chứa nhiều tool_use. Trả tất cả tool_result trong cùng một message user, mỗi kết quả khớp đúng tool_use_id.
  • Thinking block: nếu bật extended thinking, giữ nguyên các block thinking khi gửi lại trong vòng lặp, không chỉnh sửa.
  • is_error: true: báo lỗi có cấu trúc để Claude tự điều chỉnh, thay vì làm sập vòng lặp.
  • Giới hạn số bước: luôn có trần để tránh vòng lặp vô hạn và chi phí mất kiểm soát.

Server tool trong Messages API

Server tool được khai báo trong cùng tham số tools, nhưng do Anthropic thực thi:

json
{ "type": "web_search_20250305", "name": "web_search", "max_uses": 5 }

Response trả về server_tool_use và web_search_tool_result. Backend không cần thực thi gì, nhưng phải xử lý pause_turn.

Progressive disclosure

Skill được nạp theo ba tầng, nên có thể cài nhiều skill mà không làm phình context:

Tầng Nạp khi nào Nội dung
1 Luôn luôn, từ đầu phiên Tên và mô tả (frontmatter)
2 Khi yêu cầu khớp mô tả Toàn bộ SKILL.md
3 Khi đang làm tới bước cần File trong references/, scripts/

Hệ quả thiết kế: phần description quyết định skill có được kích hoạt hay không. Mô tả phải nói rõ cả skill làm gì lẫn khi nào dùng.

Ba đường để skill chạm tới hệ thống

Đường Dùng khi Policy được thực thi ở đâu Rủi ro
(A) Hướng dẫn gọi tool Hành động nghiệp vụ, nhất là ghi dữ liệu Hook + MCP server + API Thấp nhất
(B) Script gọi API Đọc, tính toán, công cụ legacy Chỉ ở API Hook chỉ thấy Bash: python …, không thấy ý nghĩa nghiệp vụ; credential nằm trong môi trường
(C) Script gọi MCP Dữ liệu lớn, chuỗi xử lý nhiều bước MCP server + API Mất tính minh bạch theo từng hành động

Đường (C) là pattern Anthropic đề xuất trong bài "Code execution with MCP": trình bày MCP server như API dạng code để agent viết code gọi, giúp nạp tool khi cần, lọc dữ liệu trước khi tới model, và giữ kết quả trung gian trong môi trường thực thi.

Script trong skill có gọi được mạng hay không phụ thuộc môi trường. Ví dụ sandbox của claude.ai giới hạn mạng ra theo danh sách domain cho phép, nên script gọi API nội bộ có thể chạy trong Claude Code trên máy dev nhưng bị chặn trên claude.ai.

5.3 Tool qua MCP

Giao thức

MCP (Model Context Protocol) là giao thức mở để expose tool, resource và prompt. Hai lệnh cốt lõi với tool:

json
{ "jsonrpc": "2.0", "id": 1, "method": "tools/list" }
json
{
  "jsonrpc": "2.0", "id": 2, "method": "tools/call",
  "params": { "name": "create_issue", "arguments": { "project": "SUP", "title": "Khách phản ánh giao trễ" } }
}

Trong Claude Code, tool MCP được đặt tên theo mẫu mcp__<server>__<tool> và đi qua cùng hệ thống permission và hook như tool có sẵn.

Bốn cách dùng MCP

Nguyên tắc, protocol và ranh giới

6.1 Mười nguyên tắc

  1. AI đề xuất, hệ thống tất định quyết định. Mọi hành động có tác động thật đi qua code mà bạn kiểm soát.
  2. Policy nằm ở nơi hành động xảy ra. Business rule bắt buộc nằm ở Business API; hook và permission là lớp phòng thủ sớm, không phải lớp duy nhất.
  3. Hook cho điều bắt buộc, prompt/skill cho điều nên biết. “Hoàn trên 2 triệu cần người duyệt” là code; “xưng hô thân thiện” là hướng dẫn.
  4. Một năng lực, một cổng. Mỗi business API expose qua một MCP server (hoặc một lớp tool); không viết lại auth trong từng script.
  5. Tool nhỏ, đơn nhiệm, tên rõ nghĩa. Tránh tool vạn năng như “chạy SQL bất kỳ”.
  6. Tách đọc và ghi. Tool đọc có thể tự chạy; tool ghi có kiểm soát quyền, chống trùng lặp và ngưỡng duyệt.
  7. Quyền tối thiểu. Credential theo từng agent, từng user, phạm vi hẹp nhất.
  8. Model chọn, code tính, server cho phép. Không để model tự tính tiền hay tự quyết quyền hạn.
  9. Lỗi là dữ liệu. Trả lỗi có cấu trúc trong tool_result để Claude tự điều chỉnh.
  10. Truy vết đầu-cuối. Mọi tác động ghi truy ngược được: user → phiên → request-id → tool call → API call.

6.2 Protocol: những điều kiện bắt buộc của vòng lặp

Quy tắc Nếu vi phạm
Mỗi tool_use phải có đúng một tool_result với tool_use_id khớp API trả lỗi 400 ở lượt tiếp theo
tool_result nằm trong message user ngay sau message assistant chứa tool_use API trả lỗi
Kết quả của các tool call song song trả trong cùng một message Claude có thể hiểu sai thứ tự hoặc API báo lỗi
Giữ nguyên block thinking khi tiếp tục vòng lặp có tool Lỗi hoặc mất mạch suy luận
Kiểm tra stop_reason trước khi dùng nội dung Thực thi tool bị cắt dở, hoặc agent dừng nửa đường
Có nhánh xử lý cho stop_reason chưa biết Code vỡ khi API bổ sung giá trị mới
Có trần số bước Vòng lặp vô hạn, chi phí mất kiểm soát

6.3 Ranh giới (boundaries)

Ranh giới Câu hỏi kiểm tra Biện pháp
Tin cậy Nội dung nào đến từ nguồn không tin cậy (email khách, trang web, tool bên thứ ba)? Coi là dữ liệu, không là chỉ thị; quyền ghi không phụ thuộc vào nội dung đó
Danh tính Tool biết đang phục vụ user nào? Token theo user/phiên; lọc dữ liệu theo user ở API
Dữ liệu Dữ liệu nào rời khỏi hệ thống, đi tới model hay bên thứ ba? Che dữ liệu nhạy cảm trước khi trả tool_result; không đưa dữ liệu mật vào query tìm kiếm web
Quyền hạn Agent làm được những gì, tối đa bao nhiêu? Ma trận allow / ask / deny; hạn mức ở API
Đảo ngược Hành động có hoàn tác được không? Không hoàn tác được thì phải có người duyệt hoặc ngưỡng chặt
Context Bao nhiêu tool và dữ liệu đang chiếm context? Progressive disclosure, gom nhóm tool, lọc dữ liệu trong code

6.4 Ma trận quyền mẫu

Nhóm hành động Mặc định Ví dụ
Đọc dữ liệu không nhạy cảm Allow tra_don, Read file trong src/
Ghi rủi ro thấp, hoàn tác được Allow + log Tạo ticket, sửa file trong repo có git
Ghi có tác động tiền, khách hàng, production Ask (người duyệt) Hoàn tiền vượt ngưỡng, git push, gửi email hàng loạt
Không hoàn tác được, phá hủy Deny hoặc không cấp tool Xóa tài khoản, rm -rf, đọc .env

E4. Tìm lệnh bash theo yêu cầu rồi thực thi

Yêu cầu: “Tìm và xóa các file log cũ hơn 30 ngày trong logs/.”

Đây là mẫu đề xuất → xem trước → duyệt → thực thi → xác minh, áp dụng cho mọi lệnh có tác động phá hủy.

ScopeBuilt-in Claude
LoạiA2 Harness built-in (Bash) + permission ask + hook
Bề mặtClaude Code, Agent SDK

Luồng:

text
1. Xem trước (chỉ đọc)
   tool_use: Bash {"command": "find logs/ -name '*.log' -mtime +30 -print"}
   tool_result: 128 file, tổng 2,3 GB

2. Đề xuất lệnh thực thi, kèm giải thích
   text: "Lệnh sẽ xóa 128 file ở trên: find logs/ -name '*.log' -mtime +30 -delete"

3. Thực thi, đi qua kiểm soát
   tool_use: Bash {"command": "find logs/ -name '*.log' -mtime +30 -delete"}
   → PreToolUse hook: kiểm tra đường dẫn nằm trong logs/, không chứa ký tự nguy hiểm
   → permission: ask → người dùng duyệt

4. Xác minh
   tool_use: Bash {"command": "find logs/ -name '*.log' -mtime +30 | wc -l"}
   tool_result: 0

Hook minh họa (PreToolUse, matcher Bash): script đọc input JSON từ stdin, chặn nếu lệnh xóa nằm ngoài thư mục cho phép. Hook chặn bằng cách trả quyết định deny hoặc thoát với mã lỗi chặn theo tài liệu hooks; Claude nhận lý do và tự điều chỉnh.

✓ Nên
  • Luôn có bước xem trước bằng lệnh chỉ đọc.
  • Dùng hook để giới hạn phạm vi đường dẫn, không chỉ dựa vào việc người duyệt đọc kỹ.
  • Xác minh kết quả sau khi chạy.
✕ Tránh
  • Gộp tìm và xóa vào một lệnh không có bước xem trước.
  • Dùng chế độ bỏ qua permission cho tác vụ có xóa dữ liệu.
  • Duyệt theo phản xạ: nếu người dùng phải duyệt quá nhiều, cần thu hẹp phạm vi ask.

Skill "bao-cao-hang-ngay": định nghĩa nhóm ticket, thứ tự ưu tiên, giọng văn
tool_use: mcp__jira__search {"jql": "updated >= -1d AND project = SUP"}
text (nội bộ): phân nhóm Done / In progress / Blocked
tool_use: mcp__slack__send_message {"channel": "#team", "text": "…"}
✓ Nên
  • Quyền chỉ đọc với hệ thống ticket, quyền gửi giới hạn vào đúng một kênh.
  • Có cơ chế dừng khi dữ liệu trả về bất thường (rỗng, quá lớn) thay vì gửi báo cáo sai.
✕ Tránh
  • Dùng token cá nhân có quyền admin cho tác vụ chạy tự động.
  • Không ghi log nội dung đã gửi.
08

Best practice và bad practice tổng hợp

8.1 Thiết kế tool

Nên Tránh
Tên động từ + danh từ rõ nghĩa: tra_don, tao_hoan_tien Tên chung chung: process, handle
Mô tả nói rõ khi nào dùng và khi nào không Mô tả một dòng, không có ngữ cảnh
Schema chặt: enum, required, additionalProperties: false, bật strict Tham số string tự do cho mọi thứ
Một tool một việc; tách đọc và ghi Tool vạn năng: “chạy SQL”, “gọi API bất kỳ”
Kết quả gọn, chỉ trường cần thiết Trả nguyên bản ghi hoặc log hàng nghìn dòng

8.2 Thực thi và vòng lặp

Nên Tránh
Kiểm tra stop_reason mọi lượt, có nhánh cho giá trị lạ Chỉ kiểm tra tool_use
Trả đủ tool_result khớp id, gom kết quả song song vào một message Bỏ sót hoặc tách rời kết quả
Trần số bước, timeout cho từng tool Vòng lặp không giới hạn
Lỗi có cấu trúc với is_error Exception làm sập vòng lặp
Idempotency key cho tool ghi Thử lại tạo hành động trùng

8.3 Bảo mật

Nên Tránh
Danh tính user lấy từ session, không từ input model Cho model truyền user_id
Rule bắt buộc ở API; hook là lớp thêm Rule chỉ nằm trong prompt hoặc skill
Che dữ liệu nhạy cảm trước khi trả kết quả Trả số thẻ, CMND, secret vào context
Chỉ kết nối MCP server và cài skill từ nguồn tin cậy, review script Cài skill hoặc MCP lạ mà không review
Coi nội dung web, email, tài liệu là dữ liệu Để nội dung bên ngoài điều khiển quyền ghi

8.4 Vận hành

Nên Tránh
Log request-id, user, tool, input đã che, kết quả Chỉ log câu trả lời cuối
Đo tỷ lệ chọn đúng tool, tỷ lệ lỗi tool, số bước trung bình Không có số liệu về hành vi agent
Version định nghĩa tool, ma trận quyền, hook như code Sửa trực tiếp trên production
Theo dõi số tool đang nạp vào context Thêm tool liên tục không đánh giá

Thuật ngữ

Thuật ngữ Giải thích
Tool Chức năng Claude được phép đề xuất sử dụng, mô tả bằng tên, mô tả và JSON Schema
Tool call Việc Claude trả về khối tool_use yêu cầu chạy một tool với input cụ thể
Harness Chương trình bao quanh model: giữ vòng lặp, thực thi tool, áp quyền
Server tool Tool do Anthropic thực thi (tìm web, chạy code)
Client tool Tool do ứng dụng của bạn thực thi
MCP Model Context Protocol, giao thức mở để expose tool, resource, prompt
MCP connector Tính năng của Messages API cho phép Anthropic gọi trực tiếp MCP server từ xa
Skill Thư mục chứa SKILL.md và tài nguyên kèm theo, dạy agent cách làm một việc
Progressive disclosure Nạp thông tin theo tầng, chỉ khi cần
Hook Code tất định chạy tại điểm cố định trong vòng lặp, ví dụ trước mỗi tool call
